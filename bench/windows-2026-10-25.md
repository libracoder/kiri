# Kiri vs Docker Desktop on Windows, 2026-10-25

One machine, one session, engines measured minutes apart with the same
docker CLI (29.9.2) and the same images, warm. Medians; the scripts are
`bench/compare.ps1` (from Windows) and `bench/compare.sh` (inside WSL).

Machine: Windows 11 Pro on a 16-core x86-64 PC, WSL 2.6.3
(NAT networking). Docker Desktop 29.8.2 with its default settings, WSL2
backend. Kiri 0.1.0 as the Linux-host engine in the Ubuntu 24.04 distro,
reached from Windows through `\\.\pipe\kiri` and `kiri bridge`.

## From Windows (`compare.ps1`)

| | Kiri | Docker Desktop |
|---|---|---|
| `docker run --rm alpine true`, median of 20 | 78 ms (min 61) | 491 ms (min 435) |
| `docker exec … true`, median of 20 | 57 ms (min 52) | 89 ms (min 84) |
| 200 MB container → host | 783 ms, 255 MB/s | 5053 ms, 40 MB/s |
| 200 MB host → container | not valid, see below | 6490 ms, 31 MB/s, all bytes arrived |

## Inside WSL (`compare.sh`, Ubuntu; Desktop through its WSL integration)

| | Kiri | Docker Desktop |
|---|---|---|
| `docker run --rm alpine true`, median of 30 | 190 ms | 669 ms |
| `docker exec … true`, median of 30 | 170 ms | 229 ms |
| 200 MB container → host | 230 MB/s | 131 MB/s |

The in-WSL latencies are dominated by the Linux docker CLI's own start
(the same CLI from Windows, over the pipe, is faster), so compare the two
engines within a table, not across them.

## Hardening cost: none

The same engine before and after the 2026-10-24/25 security hardening (a
per-container device filter, read-only and masked `/proc` paths, a layer
expansion cap, bounded request parsing), two alternating rounds inside WSL:
run 191/206 → 189/189 ms, exec 182/176 → 170/172 ms, 200 MB out 171/226 →
236/230 MB/s. Within noise.

## Caveat: host → container is not yet comparable

Piping 200 MB into `docker run -i alpine wc -c` through Kiri delivered 2.9
MB: input that arrives before the container reads it is capped at 4 MiB by
the agent and the rest is dropped (`crates/kiri-init/src/linux/agent.rs`,
`MAX_PENDING_INPUT`). Until that is replaced by flow control, Kiri's "in"
figure is meaningless and Docker Desktop's is correct. Re-measure after.
