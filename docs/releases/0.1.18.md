## New
- **A terminal built into the window.** Open it from the Terminal button in the status bar, or with ⌃\` on a Mac, Ctrl+\` on Windows or F4 on Linux. It's a normal shell on your own computer under whatever page is open, so you can watch Containers while you run `docker compose up`. Pick zsh, bash, fish, PowerShell, cmd or a WSL distro for each tab. Split right and down, find in the output, give it its own text size, and pin the tabs you keep. Kiri's `docker` and `kiri` come first on its PATH, and the shells keep running while it's hidden.

## Fixed
- **Linux: Kubernetes no longer breaks your terminals.** On a Linux computer, starting Kiri's Kubernetes (or any `--privileged` container) replaced the computer's own `/dev/ptmx`, so no new terminal could open, `sudo` included, until the next restart. A privileged container now gets its own `/dev` with copies of your devices, as on Docker, and can't change the real one.
- **Containers keep their connections while others start and stop.** Containers on a Kiri network lost their open connections whenever another container started or stopped, and a new container's first download often failed. Both are fixed.
- **Non-root servers can use ports below 1024, and `ping` works without root,** as on Docker. Images that run nginx or Caddy as a user on port 80 used to fail with `Permission denied`.
- **Container DNS keeps working when the Mac's resolver in the VM goes down.**
- **Deleting Kiri no longer breaks `docker build`.** If you dragged Kiri to the Trash while it was running (on Windows, moved or renamed its folder), it kept hold of "Build with Kiri", and every `docker build` failed. Kiri now notices it's gone, hands the builder back and stops.
- **`docker build` uses your Mac's DNS.** `RUN` steps on the default network used to switch to `8.8.8.8`, which fails on networks that block outside DNS. They now resolve names the way your Mac does.
- **Generated passwords use fresh, unbiased randomness for every character.**
- **Kiri hears about updates while it stays open.** It only checked when the window opened, so a laptop that kept Kiri open, sleeping and waking, could go days without seeing a new release. It now checks again every 6 hours, counting time asleep.
- **Settings › Resources:** both panes sit beside the tabs, the sliders look the same on Mac, Windows and Linux, and Windows no longer offers a restart that changes nothing.

## Improved
- **Firewall and network tools work in containers.** The VM's kernel now has the rest of netfilter: the nftables expressions (`reject`, `queue`, `ct label`, `socket`, `tproxy`, `log`, `limit`, `quota`), iptables matches and targets, ipset, IPVS, traffic control, socket diagnostics and the usual virtual interfaces. Rulesets that load on Docker Desktop and OrbStack now load on Kiri.
- **Tighter limits on the DNS relay** between containers and your Mac, so one container can't slow DNS down for the others.
